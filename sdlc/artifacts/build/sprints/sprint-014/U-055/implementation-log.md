# Implementation Log: U-055

## Summary

Upgraded `androidx.security:security-crypto` from `1.1.0-alpha06` to `1.1.0` stable
(SE-003 / BT-004). No code changes were required to `EncryptedPrefsSecretStore.java`
because `MasterKey.Builder` and `EncryptedSharedPreferences.create()` API surface is
identical between the alpha and the stable release.

Added `EncryptedPrefsSchemeRegressionTest.java` with 5 tests that pin the AES-256-GCM/SIV
scheme, so future dependency bumps that silently change the encryption scheme are caught by CI.

## Version Choice Justification

**Chosen: `security-crypto:1.1.0` stable** (not `1.1.0-alpha06`, not `1.0.0`).

- `security-crypto:1.1.0` stable exists (discovered in Gradle cache;
  URL: `https://developer.android.com/jetpack/androidx/releases/security#1.1.0`).
- `1.1.0` is the first non-alpha/non-beta release on the 1.1.x line.
- `MasterKey$Builder.class` confirmed present in the `1.1.0` AAR (`classes.jar` inspection).
- `1.0.0` stable uses deprecated `MasterKeys.getOrCreate()` and does NOT expose
  `setRequestStrongBoxBacked()`. Moving to it would require a code rewrite and lose
  StrongBox best-effort support — explicitly prohibited by "Existing Behavior to Preserve".
- No `1.1.0-beta01` exists on Google Maven (only `alpha01`–`alpha06` and `1.1.0` stable).
- `MasterKey.Builder` API is fully backward-compatible from alpha06 to 1.1.0 stable.
- Tink dependency upgraded from 1.7.x (alpha06) to 1.8.0 (1.1.0 stable) — improved
  cryptographic implementation, no scheme change.
- Data at rest compatibility preserved: both alpha06 and 1.1.0 use Tink-backed AES-256-GCM/SIV.

## Encryption-Scheme Regression Test (AC-3)

File: `app/src/test/java/com/zegoggles/smssync/preferences/EncryptedPrefsSchemeRegressionTest.java`

5 tests added:

| Test method | What it pins |
|-------------|-------------|
| `schemeRegression_prefKeyEncryptionScheme_mustBeAES256_SIV` | `PrefKeyEncryptionScheme.AES256_SIV.name() == "AES256_SIV"` |
| `schemeRegression_prefValueEncryptionScheme_mustBeAES256_GCM` | `PrefValueEncryptionScheme.AES256_GCM.name() == "AES256_GCM"` |
| `schemeRegression_masterKeyScheme_mustBeAES256_GCM` | `MasterKey.KeyScheme.AES256_GCM.name() == "AES256_GCM"` |
| `schemeRegression_productionCode_usesAES256_SIV_keysAnd_AES256_GCM_values` | `SchemeCapturingStore` intercepts and records the scheme constants passed by the production code's `getEncrypted()` |
| `schemeRegression_roundTrip_putAndGet_withCapturedSchemes` | Round-trip via `SchemeCapturingStore` confirms the wiring is functional |

Strategy: Robolectric cannot call real `EncryptedSharedPreferences.create()` (no real
Android Keystore JCA provider available in JVM tests). Two complementary guards are used:
1. **Constant-name pinning** (3 tests): assert enum names match the expected string values;
   any library upgrade that replaces the constant with a weaker scheme fails immediately.
2. **Builder-capture** (2 tests): `SchemeCapturingStore` overrides `getEncrypted()` to
   record what schemes the production code would have passed, then returns an in-memory
   Robolectric-backed SharedPreferences fake. Verifies the production code's intent without
   requiring a real Keystore.
